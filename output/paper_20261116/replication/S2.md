# S2. 원본 필드와 코퍼스 정제

원본 열 순서는 다음과 같다.

| 위치 | 원본 필드 | 위치 | 원본 필드 |
|---:|---|---:|---|
| 1 | 뉴스 식별자 | 11 | 사건/사고 분류3 |
| 2 | 일자 | 12 | 인물 |
| 3 | 언론사 | 13 | 위치 |
| 4 | 기고자 | 14 | 기관 |
| 5 | 제목 | 15 | 키워드 |
| 6 | 통합 분류1 | 16 | 특성추출(가중치순 상위 50개) |
| 7 | 통합 분류2 | 17 | 본문 |
| 8 | 통합 분류3 | 18 | URL |
| 9 | 사건/사고 분류1 | 19 | 분석제외 여부 |
| 10 | 사건/사고 분류2 | | |

1. `preprocess/bigkinds_schema.py`의 `COLUMN_MAP`에 있는 12개 필드를 문자열로 읽는다. 뉴스 식별자의 선행 0과 정밀도를 보존한다. `normalize()`가 일자를 YYYYMMDD로 해석하고, 언론사·제목·URL·키워드·특성추출·본문의 결측을 빈 문자열로 채운 뒤 양끝 공백을 제거한다.
2. `build()`가 분석 기간을 벗어난 행(날짜 파싱 실패 포함), ‘예외’ 또는 ‘중복’ 문자열을 포함한 분석제외 표시 행, 빈 키워드 순으로 검사한다.
3. `dedup_key()`는 공백을 제거하고 소문자로 바꾼 URL이 `http`로 시작하면 그 값을 사용한다. 그 외에는 `YYYYMMDD|언론사|제목`을 사용한다. 연도 폴더명·파일명 순으로 처리하고 파일 안의 원래 행 순서를 유지한다. 파일 안과 앞서 처리한 파일에서 같은 키의 첫 행만 남긴다.
4. 분류는 필터로 사용하지 않는다. 코퍼스에는 분류1·2가 저장된다. 토픽 입력은 원본 ‘키워드’다. 후속 월별 `run_core()`는 식별자·월·키워드 결측과 공백을 검사하고 `(month, article_id, keywords)`로 안정 정렬한 뒤 식별자 기준 첫 행을 남긴다.

**코드·입력·출력** — `preprocess/build_corpus.py`의 `iter_files()`, `read_raw()`, `normalize()`, `dedup_key()`, `is_excluded()`, `build()` 또는 `python -m preprocess.build_corpus`. 입력은 `data/raw/bigkinds/**/*.xlsx`와 `config/config.yaml`, 출력은 `data/processed/corpus/news_corpus.parquet` 및 `corpus_monthly_counts.csv`다. Phase 5.6 후속 코드는 `analysis/validate_strict_oos_forecast_v4.py::run_core`다.

**환경·검산** — Python 3.13.15, pandas 3.0.5, openpyxl 3.1.5, PyArrow 25.0.1. 당시 작업 기록(`docs/history/cursor_progress.log`)은 원본 998,020, 제외 플래그 53,194, 빈 키워드 141, 중복 키 12,976, 보존 931,709를 보고한다. 이번 구성에서는 원본·최종 건수, 분류 대응, 기준 코퍼스 SHA-256을 재검증했다. 단계별 제거 건수는 당시 기록이며, 엑셀에서 Parquet을 새로 쓰는 작업은 실행하지 않았다. Phase 5.6 메타데이터의 후속 제외 건수는 0이다.
