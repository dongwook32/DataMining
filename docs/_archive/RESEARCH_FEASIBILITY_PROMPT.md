# 반드시 수행할 테스트 (가능한 것은 실제로 실행)

## A. 데이터 가용성 점검
1. `data/raw/news.csv`, `data/raw/ecos.csv`, `data/processed/*` 존재 여부 확인
2. 뉴스가 있으면:
   - 행 수, 날짜 min/max, 월별 기사 수, 제목/본문(요약) null 비율
   - 연구 기간으로 쓸 수 있는 개월 수 계산
3. ECOS가 있으면:
   - indicator 목록, CCSI/KOSPI/환율/금리 각각의 기간·결측
4. 네이버 뉴스 API만으로 과거 장기 시계열이 불가능한지 README/코드 근거로 명시
5. 빅카인즈·네이버 데이터랩은 이 환경에서 자동 수집 가능한지(계정/파일 유무) 확인하고,
   없으면 “수동 수집 필요”로 표시 (실패로 간주하지 말 것)

## B. 기존 파이프라인 동작 점검
1. 의존성/`requirements.txt` 확인
2. 설정 파일(`config/config.yaml`, `.env` 존재 여부) 확인. 시크릿 값은 출력하지 말 것
3. 가능하면 읽기 안전한 범위에서:
   - `python -m analysis.run_pilot` 또는 관련 모듈 import/소량 실행
   - 실패 시 에러 원인과 해결책 기록
4. ENSI↔CCSI 겹치는 개월 수가 충분한지 확인 (부족하면 파일럿 한계로 명시)

## C. 국면 탐지 최소 파일럿 (핵심)
기존 뉴스 데이터가 있으면 아래를 **최소 구현 또는 노트북/스크립트 수준으로** 시도하라.
데이터가 너무 적으면 왜 부족한지 수치로 보고하고, 합성/샘플로라도 파이프라인 골격만 검증하라.

최소 성공 기준:
1. 뉴스 텍스트(title+content)로 토픽 분리 (간단하면 sklearn LDA 또는 키워드 룰 기반 프록시 가능)
2. 월별 토픽 비중 또는 월별 dominant 국면 라벨 생성
3. 국면 라벨이 해석 가능한지 샘플 3개월 이상 출력
4. 가능하면 ECOS와 월별 merge 후 국면별 평균 표 1개 생성

산출 파일 권장 경로:
- `data/processed/feasibility_regime_monthly.csv`
- `docs/feasibility_report.md` (최종 보고서)

코드는 최소화하고, 연구 계획서의 Step 1(파일럿) 범위를 넘기지 마라.
빅카인즈 크롤링/우회 수집, 네이버 뉴스 무단 크롤링은 하지 마라.

## D. 검색 데이터 실현성
1. 네이버 데이터랩(2016-01-01~) 제약과 상대지수 특성을 정리
2. 현재 레포에 검색 트렌드 파일이 있는지 확인

## 사용 방법

1. Agent 모드에서 새 채팅을 연다.
2. 위 **복사해서 사용할 프롬프트** 전체를 붙여넣는다.
3. 실행이 끝나면 `docs/feasibility_report.md`의 Verdict를 확인한다.

## Verdict 해석

| Verdict | 의미 | 다음에 할 일 |
|---------|------|----------------|
| Go | 파일럿·본연구 경로가 열림 | Step 2 본데이터(빅카인즈·데이터랩) 수집 |
| Conditional Go | 파일럿은 가능, 본연구는 데이터 补充 필요 | 보고서 Blockers부터 해소 |
| No-Go | 현재 설계로 진행 어려움 | 주제/데이터 전략 재설계 |
