# 저장소 정리 및 실행 통합

목표: 연구 데이터와 분석 계산을 보존하면서 최상위 파일을 역할별로 이동하고,
`python run.py` 한 줄로 기존 결과 대시보드를 연다.

설계: 기존 analysis/api/preprocess/config 구조는 유지한다. 표시와 실행 명령을
datamining 패키지로 분리하고 보고서는 docs/validation, 요약 산출물은 output/summary로 모은다.
전체 소스를 새 src 구조로 옮기면 기존 모듈 실행 및 연구 재현 경로가 광범위하게 깨지므로
기존 모듈을 유지하면서 진입점과 출력 경로를 통합한다. 기본 실행에는 추가 의존성이 없다.

- [x] 변경 전 소스·문서·미추적 파일 백업 및 ZIP 무결성 확인
- [x] CLI 통합 테스트: 다른 작업 디렉터리에서 help/terminal, 실제 HTTP 요청, 잘못된 포트
- [x] 진입점, 공통 경로, 터미널 표시 및 요약 분석 모듈 분리
- [x] 보고서·템플릿 이동, 동일한 중복 출력 및 임시 렌더링 제거, 관련 참조 수정
- [x] README 실행/복원 방법 갱신
- [x] 수정 파일만 복원하고 후속 수정 충돌은 거부하는 복원 스크립트 제공
- [x] 전체 테스트, 실제 출력 및 복원 사본 검증

복원 범위: .backups/cleanup-20261116에 변경 전 파일과 변경 목록을 기록한다.
data, .venv, .git은 수정하지 않는다. output의 기존 논문 파일과 미추적 소스는 보존한다.
성능 최적화 범위는 저장된 결과를 즉시 표시하는 실행 경로와 불필요한 중복 출력 제거이다.
통계 모델 재학습 및 연구 수치 변경은 이 작업에 포함하지 않는다.
